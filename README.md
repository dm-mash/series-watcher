# series-watcher

Трекер выхода сериалов: следит за расписанием, хранит его в SQLite и показывает,
когда выходит следующий эпизод. Данные берутся из [TVmaze](https://www.tvmaze.com).

## Данные и лицензия

Всё, что показывает сервис, приходит из TVmaze. Данные TVmaze лицензированы
CC BY-SA 4.0, ссылка на tvmaze.com обязательна: она стоит в выводе CLI и в
ответах бота.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
cp .env.example .env      # необязательно: всё работает и без него
```

## Команды

```bash
series-watcher add "Severance"          # найти и добавить
series-watcher add "dark knight"        # несколько совпадений — выбрать номер
series-watcher add dark knight --pick 2
series-watcher add --id 44933           # добавить по id TVmaze
series-watcher list                     # что отслеживается и когда следующий эпизод
series-watcher check                    # опросить расписание и показать, что пора сообщить
series-watcher run                      # опросить и разослать уведомления
series-watcher run --dry-run            # показать тексты сообщений, не отправляя
series-watcher digest --days 7          # сводка по ближайшим дням
series-watcher digest --recommend       # та же сводка с подбором сериалов
series-watcher seed                     # с чего начать, когда список пуст
series-watcher where                    # где смотреть: показать и добавить ссылки
series-watcher recommend --limit 5      # подобрать сериалы по вашему списку
series-watcher recommend --reject 12345 --reject-kind already_watched
series-watcher bot                      # разговорный слой: опрос Telegram и ответы
series-watcher bot --once               # один заход и выход (удобно для cron)
```

`check` ничего не помечает как отправленное — это только детектор. `run` шлёт
сообщения и ставит отметку только после успешного ответа Telegram: упавшее
сообщение не должно потерять эпизод навсегда.

## Атрибуция TVmaze

Подпись «Данные: TVmaze (CC BY-SA 4.0), https://www.tvmaze.com» приписывается
только к тем ответам, где есть данные TVmaze: названия, время эфира, рейтинг,
ссылки. Служебные ответы («Не понял, что нужно», «Пока ничего нового не вышло»)
остаются чистыми.

## Тихий режим

С `QUIET_HOURS` (по умолчанию `23-8`, зона пользователя) сообщения не отправляются
ночью, а ждут утра: эпизод остаётся неотмеченным и уйдёт следующим запуском.
Пустая `QUIET_HOURS=` выключает режим.

## Как это устроено

Всё расписание приходит из одного источника, но код написан так, чтобы это было
не «пока не понадобится»:

- **`ScheduleSource`** — протокол из семи методов: найти, отдать карточку, отдать
  эпизоды, состав, другие работы человека, расписание. Сегодня реализация одна
  (TVmaze), но подключить вторую — новая реализация интерфейса плюс одна строка в
  `schedule.build_source`. Ядро, база и рекомендатели об этом не знают.
- **Нейтральные модели.** Ни база, ни сервис не видят полей источника: время
  эфира приходит как UTC, идентификатор — как строка, а сериал в базе опознаётся
  ключом `«источник:идентификатор»`.
- **Рекомендатели — сменяемые стратегии.** Сейчас одна, по авторству и жанрам;
  модельная или внешний поиск подключаются регистрацией класса
  (`recommend --strategy <имя>`).

Одновременной работы нескольких источников расписания пока нет: это потребовало бы
согласования противоречий («какое расписание истинно»), а выигрыш неочевиден.

## Рекомендации

Рекомендателей два, выбирается флагом `--strategy`:

| `--strategy` | что делает | нужна ли модель |
| --- | --- | --- |
| `crew` (по умолчанию) | общее авторство и жанры с вашими сериалами | нет |
| `model` | модель выбирает из того, что идёт в эфире, и объясняет выбор | да |

Подбор по умолчанию опирается на авторство, а не на жанры, и работает без единого
ключа: всё берётся из TVmaze (`/shows/{id}/crew` и `/people/{id}/crewcredits`).

`model` отличается не тем, что «модель умнее», а тем, что она видит описания.
Правила умеют считать общее авторство и жанры, а настроение — «что-то лёгкое на
вечер» — они не понимают вовсе. Кандидаты при этом настоящие: модель выбирает из
того, что идёт в эфире сейчас, и всё, чего в списке нет, отбрасывается. Без
такой проверки она перечислила бы классику, которой в эфире нет и которая давно
закончилась.

```bash
series-watcher recommend --strategy model --mood "что-то лёгкое на вечер"
```

В чате способ выбирается словами, и в любом месте фразы:

| фраза в чате | что сделает |
| --- | --- |
| «посоветуй» | правила: авторство и жанры, быстро и без модели |
| «посоветуй моделью» | модель выберет сама |
| «посоветуй по авторству» | явно правила, даже если пожелание тоже названо |
| «посоветуй что-нибудь лёгкое на вечер» | модель: пожелание словами она понимает |
| «посоветуй моделью похожее на Slow Horses» | модель, ориентир — этот сериал |

Под каждым ответом есть кнопка переключения: «Подобрать моделью» или «Подобрать
по авторству». Она несёт с собой весь вопрос — пожелание, ориентир и количество, —
поэтому отвечает на тот же вопрос, а не на новый. Если переключились с модели на
правила при заданном пожелании, бот честно пишет, что правила пожелание не
учитывают: они считают общее авторство и жанры, а «комедийное» для них — просто
слова.

Названное словом не зависит от модели: «посоветуй моделью» разбирается
правилами, даже если модель в этом уверенно ошиблась.

Если в запросе назван сериал («порекомендуй похожее на Slow Horses»), сигналы
берутся только по нему, а не по всей библиотеке; без названия — по всему списку.
Под каждым кандидатом — одна короткая фраза «почему» (модель, без модели — факты
из API) и две кнопки: «Отслеживать», чтобы подписаться прямо из подборки, и
«Не интересно», которая записывает отказ в базу.

Похожих может оказаться меньше, чем просили: список пополняется добором — это
просто хорошие сериалы из того же окна эфира, и в ответе они помечены как
«добор», чтобы их нельзя было спутать с похожими. При явном «похожее на X» добора
нет: спросили про X — значит, и отвечаем про X.

Сколько выдадут — не решается, а выживает отбором: потолок пять (или сколько
назвали: «топ-3», «штук 2» — понимается), а дальше `Scripted`, рейтинг ≥ 6.5, не
отслеживается, не отклонён, не закончен и есть хоть одна общая причина.
Законченные не выдаём: трекер ждёт следующего эпизода, а начать такой сериал
можно и без подписки. Неизвестный статус за законченный не считается. Нашлось меньше, чем
просили, — так и пишем: «просили 5, нашлось 3». Молча сокращать хуже: человек
решает, что сломалось. Кандидаты берутся из расписания ближайших трёх дней: без
даты TVmaze отдаёт лишь то, что идёт прямо сейчас, и после отсева оттуда не
остаётся почти ничего.

Роли распознаются по семейству, потому что у TVmaze они гранулярные: «Staff
Writer» — это сценарист, «Executive Producer» и «Co-Producer» — продюсер, а вот
«First Assistant Director» и «Director Of Photography» режиссёрами не считаются.
Вес: создатель больше, режиссёр и сценарист — меньше, продюсер — меньше всех
(с одного сериала берём первых пятерых, остальные — шум). Актёры не используются:
они пересекаются у всего подряд. Отсев: только
`Scripted`, порог рейтинга (`--min-rating`, по умолчанию 6.5), плюс всё
отслеживаемое и всё, от чего уже отказались (`--reject`). Объяснение собирается
из полей ответа API: `создатель: Dan Erickson`, `режиссёр: Adam McKay`, `жанры: Drama`.

## Модель

Один адрес — любой OpenAI-совместимый эндпоинт. Облачные варианты из `.env.example`:
Groq (`https://api.groq.com/openai/v1`, `openai/gpt-oss-120b` — строгая JSON-схема) и
Mistral (`https://api.mistral.ai/v1`, `mistral-large-latest`).

Строгий `json_schema` поддерживают не все модели: клиент один раз пробует его, а при
отказе (HTTP 400) переходит на `json_object` и объясняет формат в самом запросе.

Модель делает пять вещей, и все пять — необязательные:

1. **описание → название.** «добавь сериал про офис, где людей разделяют на
   части» и «что за сериал, где людям режут память» → модель называет название →
   дальше обычный поиск по названию. Описание переживает и обрывки: модель
   специально ищет по тому, что в нём есть, а не по точному совпадению. Какое
   именно название прозвучит — зависит от описания: размывчатое подходит многим
   сериалам, и выбор остаётся за моделью. Если модель не ответила, так и
   говорится — «модель не ответила», а не «сериала нет»;
2. **выбор из неоднозначной выдачи.** «добавь sherlock» в каталоге даёт шесть
   похожих, и модель выбирает сама. Если она не уверена — говорит «не уверена», и
   бот показывает варианты кнопками: решение остаётся за человеком. Без модели
   не выбирает никто, и варианты показываются всегда;
3. **сжатие описания эпизода** до одной-двух фраз на русском — пишется один раз и лежит в базе;
4. **краткая строка о самом сериале** — перевод и сжатие сводки TVmaze;
5. **объяснение рекомендации** одной фразой по фактам из ответа API.

Факты модель не выдумывает: ей дают то, что пришло из TVmaze, и просят собрать фразу.

## Разговорный слой

`bot` читает сообщения long polling и отвечает на намерения: `что нового`,
`список`, `добавь ...`, `что за сериал ...`, `где смотреть ...`,
`отметь ... серию`, `перестань следить за ...`, `дайджест`, `посоветуй ...`.

История диалога не хранится — каждая реплика самодостаточна и отвечается
запросом к базе.

Намерения разведены явно: `список` — это отслеживаемые сериалы с ближайшим
эфиром, `дайджест` — расписание на неделю. Модели велено возвращать `unknown`,
если запрос ни под что не подходит, а не подставлять соседнее намерение.

Разбор фразы делает модель строго по JSON-схеме (`LLM_BASE_URL`, `LLM_MODEL`,
`LLM_API_KEY` — любой OpenAI-совместимый эндпоинт). Если модель не настроена или
ответ неуверенный, срабатывают правила по словам-маркерам, а когда и они не
уверены — бот предлагает кнопки вместо догадок.

## Раздачи (torrent)

Если установлен пакет `torrent-search-mcp` (ключей не нужно — трекеры публичные),
сервис умеет искать раздачу для серии, которая только что вышла:

```bash
pip install torrent-search-mcp
export TORRENT_SEARCH=1        # в .env или окружении — включить поиск
series-watcher torrents        # найти для недавно вышедших серий (с учётом паузы)
series-watcher torrents --force  # проигнорировать паузу и поискать сейчас
```

Как это работает:

- после того как серия вышла в эфир и мы сообщили о ней, ищем раздачу **не чаще
  раза в 6 часов** и **не дольше 3 суток** после эфира (настраивается
  `TORRENT_RETRY_HOURS` / `TORRENT_RETRY_DAYS`). Повторы нужны: раздачи
  появляются с задержкой и сначала часто без сидов;
- за один запуск ищем не больше трёх серий (`MAX_TORRENT_SEARCHES_PER_RUN`),
  чтобы не мешать опросу расписания;
- найденное сохраняем в таблицу `torrents` и присылаем один раз отдельным
  сообщением. Повторно о той же серии не пишем: отметка живёт в базе, а у
  каждого сериала каждая новая серия — это отдельная находка;
- фильтруем мусор: без сидов, не про ту серию, игры/репаки, пакеты вида
  «S02E05-08»;
- показываем каждую раздачу тремя строками: название с размером и сидами,
  ссылка на страницу трекера и отдельная magnet-ссылка. Магнет дозапрашивается
  у трекера только для тех раздач, что реально показываем, и кэшируется в базе;
- сообщения в Telegram собираются с HTML-разметкой: названия жирные, ссылки
  кликабельные, всё, что пришло от API, экранируется. В терминале теги
  снимаются — там `magnet:?xt=…` полезнее слова «magnet». Подпись про источник
  данных в этих ответах идёт мелкой строкой в конце, а в сообщении о раздачах
  её нет вовсе: данных TVmaze там нет

Спросить конкретную серию можно и по запросу, минуя паузу между попытками:

- в чате: «где скачать S02E05 Severance» или просто «где скачать S02E05», если
  сериал один. Если сериалов много и название не названо, бот попросит уточнить;
- из командной строки: `series-watcher torrents --force` ищет по всем недавно
  вышедшим сериям, `--dry-run` показывает, что было бы отправлено.

Поиск включается флагом `TORRENT_SEARCH` и по умолчанию **выключен**: пакет
ставится отдельно, а без него сервис работает как обычно.

Ответственность: трекеры отдают раздачи третьих рук, без гарантий и без
проверки содержимого. Скачивание — на ваше усмотрение и под вашу
ответственность.

## Где смотреть

Источник один — свой файл `CUSTOM_SOURCES_PATH`: id сериала TVmaze и ссылки. Ссылка
ниоткуда не выдумывается: пока её нет, сообщение говорит, что не настроено, и
сразу даёт готовую команду.

```bash
series-watcher where                                        # что нашли по всем сериалам
series-watcher where --add 44933 --url https://… --provider Кинопоиск --kind подписка
```

Глобальные ключи `--db PATH` и `--tz ZONE` перекрывают `DB_PATH` и `TZ`.
Код возврата: `0` — всё прошло, `1` — ошибка, `2` — нужно выбрать вариант.

Время эфира хранится в UTC, `--tz` (по умолчанию `TZ`, иначе системная зона)
нужен только для вывода.

## Окно уведомлений

`check` смотрит назад только на `NOTIFY_LOOKBACK_HOURS` часов (по умолчанию 72).
Без окна добавление сериала с историей превратилось бы в поток из сотен старых
эпизодов. Ключ эпизода — `(show_id, season, number)`, а не время: перенос эфира
меняет дату, но не эпизод, поэтому перенесённый эпизод не приходит повторно.

## Что отключается без ключей

Сервис работает без единого ключа и говорит, что именно отключено:

| Переменная | Без неё |
| --- | --- |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления не отправляются, работает только CLI |

`TELEGRAM_CHAT_ID` можно не задавать: бот запоминает чат, откуда с ним заговорили,
и уведомления идут туда же. Явный `TELEGRAM_CHAT_ID` имеет приоритет. Чтобы начать
переписку, нужно один раз нажать **Start** в диалоге с ботом: писать первым он не может.
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | разбор фразы работает по правилам, кнопки вместо догадок; описание сериала не сверяется с каталогом; описания эпизодов не переводятся |

Поиску раздач ключ не нужен вовсе, но нужен сам пакет: без `torrent-search-mcp`
(и флага `TORRENT_SEARCH`) сервис работает как обычно и лишь не ищет раздачи — об
этом он и говорит, если его спросить.



Ключи читаются только из окружения, в репозитории их нет и быть не должно.

## Устройство

```
series_watcher/
├── config.py     # окружение, зона времени, деградация без ключей
├── db.py         # сериалы, эпизоды, отправки, отказы, HTTP-кэш
├── models.py     # ShowRecord, EpisodeRecord: то, что видит ядро
├── schedule.py   # ScheduleSource: протокол источника + реализация TVmaze
├── strategies/   # рекомендатели: один интерфейс, разные реализации
├── finders/      # поиск раздач: один интерфейс, реализация одна (torrent-search-mcp)
├── tvmaze.py     # HTTP-клиент TVmaze: ретраи, лимит запросов, кэш
├── notify.py     # Telegram: отправка, long polling, отметки о доставке
├── llm.py        # клиент модели: ретраи и ответ по JSON-схеме
├── nlu.py        # фраза -> намерение и аргументы, правила как запасной путь
├── bot.py        # разговорный слой поверх сервиса
├── sources/      # «где смотреть»: свой файл ссылок
├── service.py    # добавление сериала, список, опрос, рассылка
└── cli.py        # add / list / check / run / digest / seed / where / recommend / bot
```

Замысел целиком — в [PLAN.md](PLAN.md).

## Фоновая работа

Готовые юниты лежат в `deploy/`. Пути в них абсолютные и под этот каталог —
поправьте `WorkingDirectory` и `ExecStart` под свой путь.

```bash
sudo cp deploy/series-watcher.service deploy/series-watcher.timer /etc/systemd/system/
sudo cp deploy/series-watcher-weekly.service deploy/series-watcher-weekly.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now series-watcher.timer series-watcher-weekly.timer
systemctl list-timers 'series-watcher*'
```

`series-watcher.timer` опрашивает расписание каждые 15 минут и шлёт уведомления о
новых эпизодах. `series-watcher-weekly.timer` раз в неделю, по понедельникам,
отправляет дайджест с подбором.

Разговорный бот — отдельный процесс, ему нужен токен:

```bash
systemd-run --user --unit=series-watcher-bot \
  /home/smash/series-watcher/.venv/bin/series-watcher bot
```

Ключи берутся из `.env` рядом с проектом: systemd их не читает, поэтому переменные
окружения, нужные сервису, задаются в самом юните или в `EnvironmentFile`.

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Тесты не ходят в сеть: api.tvmaze.com закрыт `httpx.MockTransport`, ответы
берутся из сохранённых реальных запросов в `tests/fixtures/`.
