# series-watcher

Трекер выхода сериалов: следит за расписанием, хранит его в SQLite и показывает,
когда выходит следующий эпизод. Данные берутся из [TVmaze](https://www.tvmaze.com).

## Данные и лицензия

Всё, что показывает сервис, приходит из TVmaze. Данные TVmaze лицензированы
CC BY-SA 4.0, ссылка на tvmaze.com обязательна: она стоит в выводе CLI и в
ответах бота.

## Установка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
cp .env.example .env      # необязательно: всё работает и без него
```

## Команды

```bash
series-watcher add "Severance"          # найти и добавить
series-watcher add "dark knight"        # несколько совпадений — выбрать номер
series-watcher add dark knight --pick 2
series-watcher add --id 44933           # добавить по id TVmaze
series-watcher list                     # что отслеживается и когда следующий эпизод
series-watcher check                    # опросить расписание и показать, что пора сообщить
series-watcher run                      # опросить и разослать уведомления
series-watcher run --dry-run            # показать тексты сообщений, не отправляя
series-watcher digest --days 7          # сводка по ближайшим дням
series-watcher recommend --limit 5      # подобрать сериалы по вашему списку
series-watcher recommend --reject 12345 --reject-kind already_watched
series-watcher bot                      # разговорный слой: опрос Telegram и ответы
series-watcher bot --once               # один заход и выход (удобно для cron)
```

`check` ничего не помечает как отправленное — это только детектор. `run` шлёт
сообщения и ставит отметку только после успешного ответа Telegram: упавшее
сообщение не должно потерять эпизод навсегда.

## Тихий режим

С `QUIET_HOURS` (по умолчанию `23-8`, зона пользователя) сообщения не отправляются
ночью, а ждут утра: эпизод остаётся неотмеченным и уйдёт следующим запуском.
Пустая `QUIET_HOURS=` выключает режим.

## Рекомендации

Подбор опирается на авторство, а не на жанры, и работает при любом наборе ключей:

1. `Creator` из TVmaze (`/shows/{id}/crew`) — ключ не нужен;
2. режиссёры и сценаристы из TMDB — связка по `externals.thetvdb`, нужен ключ;
3. жанры — страховка, когда ключа нет.

Актёры не используются: они пересекаются у всего подряд. Отсев: только `Scripted`,
порог рейтинга (`--min-rating`, по умолчанию 6.5), плюс всё отслеживаемое и всё,
от чего уже отказались (`--reject`). Объяснение собирается из полей ответа API:
`жанры: Drama`, `создатель: Dan Erickson`, `режиссёры и сценаристы: ...`.

## Разговорный слой

`bot` читает сообщения long polling и отвечает на намерения: `что нового`,
`добавь ...`, `где смотреть ...`, `отметь ... серию`, `перестань следить за ...`,
`дайджест`, `посоветуй ...`. История диалога не хранится — каждая реплика
самодостаточна и отвечается запросом к базе.

Разбор фразы делает модель строго по JSON-схеме (`LLM_BASE_URL`, `LLM_MODEL`,
`LLM_API_KEY` — любой OpenAI-совместимый эндпоинт). Если модель не настроена или
ответ неуверенный, срабатывают правила по словам-маркерам, а когда и они не
уверены — бот предлагает кнопки вместо догадок.

## Где смотреть

Источники перебираются по очереди, отвечает тот, кто нашёл. Ничего не нашлось —
в сообщении так и написано, ссылки не выдумываются.

| Источник | Что нужно |
| --- | --- |
| `свой` | файл `CUSTOM_SOURCES_PATH` с id сериала TVmaze и ссылками |
| `justwatch` | `JUSTWATCH_API_KEY` и `JUSTWATCH_COUNTRY` |

Глобальные ключи `--db PATH` и `--tz ZONE` перекрывают `DB_PATH` и `TZ`.
Код возврата: `0` — всё прошло, `1` — ошибка, `2` — нужно выбрать вариант.

Время эфира хранится в UTC, `--tz` (по умолчанию `TZ`, иначе системная зона)
нужен только для вывода.

## Окно уведомлений

`check` смотрит назад только на `NOTIFY_LOOKBACK_HOURS` часов (по умолчанию 72).
Без окна добавление сериала с историей превратилось бы в поток из сотен старых
эпизодов. Ключ эпизода — `(show_id, season, number)`, а не время: перенос эфира
меняет дату, но не эпизод, поэтому перенесённый эпизод не приходит повторно.

## Что отключается без ключей

Сервис работает без единого ключа и говорит, что именно отключено:

| Переменная | Без неё |
| --- | --- |
| `TMDB_API_KEY` | рекомендации по режиссёрам и сценаристам: остаются авторство из TVmaze и жанры |
| `JUSTWATCH_API_KEY` | «где смотреть»: отдаётся только ссылка на TVmaze |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления не отправляются, работает только CLI |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | разбор фразы работает по правилам, кнопки вместо догадок |

Форма ответа JustWatch подтверждена без ключа лишь частично: подтверждено, что
`searchTitles` отдаёт `edges`, а неизвестное поле даёт пустой список, а не падение.

Ключи читаются только из окружения, в репозитории их нет и быть не должно.

## Устройство

```
series_watcher/
├── config.py     # окружение, зона времени, деградация без ключей
├── db.py         # сериалы, эпизоды, отправки, отказы, HTTP-кэш
├── tvmaze.py     # клиент TVmaze: ретраи, лимит запросов, кэш
├── notify.py     # Telegram: отправка, long polling, отметки о доставке
├── llm.py        # клиент модели: ретраи и ответ по JSON-схеме
├── nlu.py        # фраза -> намерение и аргументы, правила как запасной путь
├── tmdb.py       # режиссёры и сценаристы по id TheTVDB
├── recommend.py  # подбор: авторство, жанры, объяснение, отказы
├── bot.py        # разговорный слой поверх сервиса
├── sources/      # «где смотреть»: свой файл, JustWatch
├── service.py    # добавление сериала, список, опрос, рассылка
└── cli.py        # add / list / check / run / digest / recommend / bot
```

Замысел целиком — в [PLAN.md](PLAN.md).

## Тесты

```bash
.venv/bin/python -m pytest -q
```

Тесты не ходят в сеть: api.tvmaze.com закрыт `httpx.MockTransport`, ответы
берутся из сохранённых реальных запросов в `tests/fixtures/`.
